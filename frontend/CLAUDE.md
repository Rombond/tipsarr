## Architecture

**SvelteKit SPA** — single-page dashboard with three tabs (Box Office, Suggestions, and Seerr). Built on Svelte 5 + shadcn-svelte components. Runs on Bun.

```
├── src/
│   ├── routes/
│   │   ├── +layout.svelte          # SvelteKit layout, wraps all pages with @render
│   │   └── +page.svelte            # Main dashboard: tabs + tab-specific components
│   ├── lib/
│   │   ├── api/
│   │   │   ├── index.ts           # Re-exports everything
│   │   │   ├── boxarr.ts          # GET /boxoffice/current, /movies/{id}, /movies/status, /weeks, /scheduler/trigger
│   │   │   ├── suggestarr.ts      # GET /jobs/suggestions, /jobs/suggestions/{action}, /automation/requests/workflow/*
│   │   │   └── seerr.ts           # GET /discover/trending, /discover/movies, /discover/tv (via /seerr-api proxy)
│   │   ├── components/
│   │   │   ├── boxoffice/
│   │   │   │   ├── boxoffice-current.svelte   # Current-week cards + refresh button
│   │   │   │   ├── movies.svelte              # Week navigation + movie status grid
│   │   │   │   └── movie-detail-modal.svelte # Movie detail modal
│   │   │   ├── suggestions/
│   │   │   │   ├── suggestion-list.svelte   # Filterable suggestion card grid
│   │   │   │   └── suggestion-modal.svelte # Detail + approve/reject buttons
│   │   │   └── seerr/
│   │   │       ├── discover-grid.svelte         # Trending/Movies/TV poster grid (read-only)
│   │   │       └── discover-detail-modal.svelte # Read-only detail view
│   │   └── assets/
│   │       └── favicon.svg
│   ├── app.html               # HTML shell
│   └── app.d.ts               # App-level declarations
├── docs/                        # API reference (OpenAPI JSON, MD docs)
├── vite.config.ts             # dev/preview proxy: /seerr-api → VITE_SEERR_URL (works around Seerr's missing CORS headers)
└── .env / .env.example        # VITE_BOXARR_URL, VITE_SUGGESTARR_URL, VITE_SEERR_URL, VITE_SEERR_API_KEY
```

### Data Flow

```
+page.svelte (tabs)
 ├── boxoffice/current → boxoffice-current.svelte → Card grid → click → movie-detail-modal.svelte
 │
 ├── suggestions → suggestion-list.svelte → Card grid → click → suggestion-modal.svelte
 │
 └── seerr (trending/movies/tv) → discover-grid.svelte → Card grid → click → discover-detail-modal.svelte
```

- `+page.svelte` manages tab state (`boxoffice` | `suggestions` | `seerr`) and dispatches to the corresponding component.
- All three tabs fetch data independently via their dedicated API clients.
- Modal components are controlled by a parent `on:click` callback; they fire an action then close.
- Seerr tab is view-only (discovery browsing) — no request creation/approval yet; that's planned as a future addition alongside merging all tabs into one page.

## API Clients

**BoxArr** (`src/lib/api/boxarr.ts`) — no auth. Uses `import.meta.env.VITE_BOXARR_URL`.

| Function | HTTP | Purpose |
|---|---|---|
| `getBoxOfficeCurrent()` | GET `/boxoffice/current` | Top 10 movies this week |
| `getMovie(id)` | GET `/movies/{id}` | Movie detail (used in modal) |
| `getMovieStatus(movieIds)` | POST `/movies/status` | Batch status check |
| `getWeeks()` | GET `/weeks` | Week list for history nav |
| `triggerRefresh()` | POST `/scheduler/trigger` | Manual refresh (manual button) |

**SuggestArr** (`src/lib/api/suggestarr.ts`) — JWT via httpOnly cookie. Uses `import.meta.env.VITE_SUGGESTARR_URL`.

| Function | HTTP | Purpose |
|---|---|---|
| `getSuggestions()` | GET `/jobs/suggestions` | Current user's recommendations |
| `retrySuggestions(ids)` | POST `/jobs/suggestions/retry` | Retry failed suggestions |
| `blacklistSuggestions(ids)` | POST `/jobs/suggestions/blacklist` | Blacklist + reject |
| `getWorkflowSuggestions(status)` | GET `/automation/requests/workflow` | Workflow suggestions |
| `approveWorkflowSuggestions(ids)` | POST `/automation/requests/workflow/approve` | Bulk approve |
| `rejectWorkflowSuggestions(ids)` | POST `/automation/requests/workflow/reject` | Bulk reject |

The `fetchWithAuth` helper in `suggestarr.ts` intercepts 401 responses, re-fetches with `credentials: 'include'`, and handles cookie-based token refresh.

**Seerr** (`src/lib/api/seerr.ts`) — static API key via `X-Api-Key` header. Requests go through the `/seerr-api` dev/preview proxy (see `vite.config.ts`) rather than `import.meta.env.VITE_SEERR_URL` directly, because Seerr doesn't send CORS headers and the browser blocks cross-origin calls otherwise.

| Function | HTTP | Purpose |
|---|---|---|
| `getTrending(page)` | GET `/discover/trending` | Trending movies + TV (mixed results, `person` entries filtered client-side) |
| `getDiscoverMovies(page)` | GET `/discover/movies` | Popularity-sorted movie discovery |
| `getDiscoverTv(page)` | GET `/discover/tv` | Popularity-sorted TV discovery |
| `posterUrl(posterPath)` | — | Prefixes a relative TMDB poster path with `VITE_TMDB_IMAGE_BASE` |

`MovieResult`/`TvResult` items already embed `title`/`name`, `posterPath`, `overview`, `voteAverage`, and optional `mediaInfo.status` (1-6 availability) — no extra enrichment calls needed.

## Component Patterns

- **Card grid**: `boxoffice-current.svelte`, `suggestion-list.svelte`, and `discover-grid.svelte` all render `Card` grids via `shadcn-svelte` (`Card`, `CardContent`, `CardHeader`).
- **Loading states**: Skeleton cards with `animate-pulse` bars.
- **Error states**: Inline text + retry button.
- **Modals**: Fixed overlay (`modal-backdrop` + `modal-dialog`) with fade/scale animations. Backdrop click or `X` button calls `handleClose`.
- **Search/filter**: Client-side `.filter()` with `.toLowerCase()` comparison on `title`.

## Configuring the Backends

Set environment variables before running:

```
VITE_BOXARR_URL=http://localhost:8080/api   # no auth
VITE_SUGGESTARR_URL=http://localhost:8080/api   # JWT via cookie
VITE_SEERR_URL=http://localhost:5055        # static API key, browser calls proxy through /seerr-api
VITE_SEERR_API_KEY=                          # sent as X-Api-Key header
```

For local testing against the SuggestArr backend, auth must be provided first via the `/api/auth` login endpoint — the UI expects a session cookie.

Seerr has no CORS support, so `vite.config.ts` proxies `/seerr-api/*` → `VITE_SEERR_URL` for both `bun dev` and `bun preview`. If you change `VITE_SEERR_URL`, restart the dev/preview server — Vite only reads env vars for the proxy target at config-load time.

## File Conventions

- `*.svelte` — Svelte 5 components (`<script lang="ts">`, `$state()`, `$:`, `@each`).
- `*.ts` — API clients and utility modules (`lib/api/`, `lib/utils.ts`).
- `cn(...)` — `clsx` + `tailwind-merge` helper from `lib/utils.ts` for composable classes.

## Svelte-Specific Notes

- Svelte 5 reactive syntax: `$state()` for writable state, `$:` for derived state, `$:` blocks for inline reactive assignments.
- `@each items as item (key)` for keyed loops; `//each` or `for..in` patterns are not used.
- Template literals inside `{...}` for interpolation, no backticks.
- Event delegation: `on:click:preventDefault` on button children inside `<a>`/other elements.
